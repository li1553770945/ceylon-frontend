# 7. 设计系统与国际化

## 7.1 视觉基调

CEYLON 是企业协作型 SaaS，界面应安静、清晰、适合长时间工作。

设计原则：

- 工作台优先信息密度和扫描效率。
- 公开首页可以更有品牌感，但不应遮蔽产品真实能力。
- 表格、工具栏、侧边栏需稳定，不因动态内容产生跳动。
- 卡片圆角和阴影克制，避免营销式堆叠。

## 7.2 品牌色

当前项目使用 `CEYLON_ORANGE` 作为主色，建议保留为主要强调色。

建议色彩角色：

| 角色 | 用途 |
| --- | --- |
| 主色 | CTA、选中态、品牌标识 |
| 成功色 | 已完成、保存成功 |
| 信息色 | 进行中、链接、提示 |
| 警告色 | 风险提示、优先级 |
| 危险色 | 删除、拒绝、错误 |
| 中性色 | 背景、边框、正文、辅助文本 |

## 7.3 主题

必须支持：

- 浅色。
- 深色。
- 跟随系统。

要求：

- 所有页面均可读。
- 表格 hover、选中、编辑态在两种主题下可区分。
- Markdown 代码块、Mermaid、LaTeX 在深浅色下可读。
- 表单错误、禁用态、loading 态在深浅色中一致。

## 7.4 组件规范

### 布局

- 公开站点使用 Public Navbar。
- 工作台使用 App Shell：侧边栏 + 顶栏 + 主内容。
- 管理后台使用 Admin Shell。

### 按钮

- 主要操作使用 contained。
- 次要操作使用 outlined/text。
- 危险操作使用 red/danger，并二次确认。
- 图标按钮必须有 tooltip 或 aria-label。

### 表格

- 列宽稳定。
- 长文本截断并支持查看完整内容。
- 内联编辑状态要明显。
- 批量选择和批量操作靠近表格工具栏。
- 空状态需要给出下一步操作。

### Dialog / Drawer

- 创建项目、创建视图、导入数据、确认删除适合 Dialog。
- 大型导入预览或复杂设置可使用 Drawer。

## 7.5 国际化

当前支持：

- `zh`
- `en`
- `ja`

新项目应保留 `messages/{locale}.json`。

要求：

- 公开页面、认证页面、工作台核心动作均国际化。
- 错误提示和空状态国际化。
- 日期、数字、价格按 locale 格式化。
- 语言偏好存储在 `localStorage` 中，通过客户端上下文切换，不反映在路由中。

## 7.6 文案结构建议

```json
{
  "common": {},
  "nav": {},
  "auth": {},
  "home": {},
  "dashboard": {},
  "project": {},
  "requirements": {},
  "settings": {},
  "admin": {},
  "blog": {},
  "errors": {}
}
```

## 7.7 可访问性

- 所有输入有 label。
- 图标按钮有 aria-label。
- Dialog 打开后焦点进入，关闭后焦点返回触发按钮。
- 表格操作支持键盘基本导航。
- 错误提示不只依赖颜色。
- 文件上传支持点击选择和拖放。
