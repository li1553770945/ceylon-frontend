# 1. 前端产品概览

## 1.1 产品定位

CEYLON 前端面向企业团队的需求管理协作场景，核心目标是把用户反馈、需求整理、版本计划、团队协作、执行状态、复盘沉淀串成一个可视化工作台。

前端需要同时服务两类体验：

| 体验 | 说明 |
| --- | --- |
| 公开站点 | 首页、定价、文档、博客、SEO、未登录用户转化 |
| 工作台 | 登录后的项目、版本视图、需求表格、团队、设置、CLI、管理员后台 |

## 1.2 用户群体

| 用户 | 主要诉求 |
| --- | --- |
| 产品经理 | 快速整理需求、按版本组织范围、跟踪状态和负责人 |
| 研发 / 测试 | 查看明确需求、筛选待办、更新状态、参与评审 |
| 运营 / 客服 | 将用户反馈导入需求池，参与需求优先级判断 |
| 团队管理员 | 管理项目成员、权限、订阅、邀请码和内容发布 |
| 本地 AI / CLI 用户 | 通过 CLI 授权让本地工具读写项目需求 |

## 1.3 前端核心价值

- 清晰：以项目、版本视图、需求表格组织复杂需求。
- 高效：支持表格内联编辑、批量操作、筛选排序、导入导出。
- 协作：成员权限、负责人、状态和评论/评审入口应清晰可见。
- 可迁移：新前端只对接自建后端 API，避免页面和数据库实现耦合。
- 国际化：当前产品支持中文、英文、日文，重构时应保留多语言能力。

## 1.4 当前实现来源

当前前端位于 `/Users/kirigaya/project/ceylon`，主要依据：

- `app/`：Next.js App Router 页面和历史 API route。
- `components/`：布局、认证、表格、导入、博客、管理后台组件。
- `stores/`：Zustand 认证与主题状态。
- `messages/`：中文、英文、日文文案。
- `types/`：核心业务类型。
- `tests/e2e` 与 `tests/api`：现有产品行为和验收线索。

## 1.5 新旧职责边界

当前项目把 Web UI 与大量业务 API route 放在同一个 Next.js 项目中。迁移后应拆分：

| 当前职责 | 新项目归属 |
| --- | --- |
| 页面、布局、表格交互、表单校验、主题、国际化 | `ceylon-frontend` |
| 登录注册、JWT、Refresh Token、用户资料、权限校验 | `ceylon-backend` |
| 项目、成员、版本视图、需求、自定义列、导入、博客、邀请码 | `ceylon-backend` |
| 头像、项目图标、导入文件、附件存储签名 | `ceylon-backend` + 对象存储 |
| Supabase Auth / Database / Storage | 不再使用 |
